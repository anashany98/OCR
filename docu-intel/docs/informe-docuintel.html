Plataforma interna de OCR, IA y recuperación documental

1. Resumen Ejecutivo

Docu-Intel es un sistema de inteligencia documental que transforma carpetas de documentos en escaneo (presupuestos, pedidos, facturas, albaranes, planos, imágenes, PDFs y Excels) en una base de conocimiento consultable mediante lenguaje natural. Combina OCR multicascada de alta precisión, embeddings semánticos, búsqueda híbrida y un asistente IA local para responder preguntas sobre la documentación empresarial.

Problema que resuelve

Las empresas de construcción y mantenimiento acumulan cientos de gigabytes de documentos por presupuesto: facturas escaneadas, pedidos, planos, correos y hojas de cálculo. Encontrar información específica ("¿cuánto costó la fontanería del hotel X?", "¿dónde está el plano de la planta baja?") requiere horas de búsqueda manual.

Valor para el negocio

  • Ahorro de tiempo: Búsqueda instantánea en lugar de revisar carpetas manualmente
  • Precisión: OCR multicascada con preprocesado específico por motor
  • Seguridad: Aislamiento por presupuesto; precios solo visible por permisos
  • Automatización: Ingesta 24h, clasificación automática, alertas de calidad
  • Escalabilidad: Workers GPU separados, procesamiento paralelo
  • Sin dependencia externa: IA local (sin envío de datos a la nube)

2.4 Búsqueda Inteligente

Tres modos de búsqueda que se combinan para máxima recall:

  • Texto exacto: BM25 sobre contenido OCR y metadatos (presupuesto, cliente, referencia)
  • Semántica: Embeddings BGE-M3 (1024 dims) con pgvector, modo query para consultas asimétricas
  • Híbrida (RRF): Reciprocal Rank Fusion que fusiona texto + semántico sin calibrar escalas
  • Reranker: Cross-encoder BGE-reranker-v2-m3 para reordenar los candidatos iniciales

2.5 Chat IA con Fuentes Verificables

Asistente en lenguaje natural que responde preguntas sobre la documentación:

  • 15+ tools internas: Búsqueda documental, presupuestos, pedidos, entidades, planos, duplicados
  • Grounding obligatorio: Solo responde con fuentes recuperadas; sin inventar datos
  • Respuesta estructurada: Secciones de Respuesta, Datos, Fuentes, Confianza y Advertencias
  • Multiidioma: Español, inglés, francés, alemán, italiano, portugués
  • Historial: Preguntas y respuestas persistidas para referencia

2.6 Planos y Cotas

Módulo especializado en extracción de información de planos técnicos:

  • Escala: Extracción de ratios 1:50, 1:100, etc.
  • Cotas textuales: Medidas en m, cm, mm con confianza
  • Habitaciones: Superficies OCR en m²
  • Anotación manual: Corrección y edición de escala y habitaciones
  • Detección de símbolos: YOLOv8 para elementos de plano

2.7 Administración y Gobierno

Panel de administración completo con 6 secciones:

  • Operativa: Métricas de procesamiento, calidad documental, alertas
  • Estado técnico: Salud de servicios, workers, disco, colas

3. Casos de Uso

3.1 Buscar un Presupuesto por Número

Escenario: Un técnico necesita encontrar el presupuesto 245745 rápidamente.
Flujo: Abre Docu-Intel → Busca "245745" → Ve el presupuesto con cliente, fecha, total y documentos asociados.
Tecnología: Búsqueda exacta por `budget_code` + BM25 sobre metadatos.

3.2 Consultar Gasto por Proyecto

Escenario: Un director pregunta "¿cuánto nos hemos gastado en el hotel Marina en marzo?"
Flujo: Escribe la pregunta en Chat IA → El sistema ejecuta `aggregate_business` → Devuelve desglose por tipo de documento con fuentes.
Tecnología: Intent router → tool `aggregate_business` → SQL exacto sobre entidades extraídas.

3.3 Revisar Documentos de Baja Calidad

Escenario: Un administrador revisa documentos que el OCR no procesó bien.
Flujo: Admin → OCR y calidad → Ve preview, texto extraído, bloques OCR → Aprueba o rechaza con motivo → Reprocesa página específica.
Tecnología: Pipeline de revisión OCR con preview, aprobación/denegación, reprocesado por página.

3.4 Consultar Medidas de un Plano

Escenario: Un instalador necesita saber las dimensiones de la cocina.
Flujo: Chat IA: "¿Cuánto mide la cocina del plano del hotel X?" → Sistema recupera habitaciones del plano → Devuelve ancho, largo, área con fuente.
Tecnología: Extracción de `plan_rooms` + `plan_dimensions` + respuesta grounded.

3.5 Integrar con Herramienta Externa

Escenario: Una herramienta de gestión de obra necesita datos de presupuestos.
Flujo: La herramienta crea sesión firmada → Ejecuta tools controladas → Recibe datos con precios solo si tiene permiso.
Tecnología: API `/integrations/v1` con API key, sesiones JWT por presupuesto, redacción automática.

Flujo de Datos Principal

  1. Ingesta: Watcher detecta archivo → registra en BD → envía job a Celery
  2. OCR: Worker renderiza PDF → cascada Tesseract→PaddleOCR→PP-Structure → guarda texto y posiciones
  3. Chunking: Texto se divide en chunks semánticos con metadatos (tipo, archivo, página)
  4. Embeddings: Chunks se vectorizan con BGE-M3 (1024 dims) → inserta en pgvector
  5. Clasificación: Tipo de documento determinado por reglas + learned patterns
  6. Extracción: Campos clave (nº factura, total, etc.) extraídos por regex y LLM
  7. Búsqueda: Queries se buscan en texto + vectores → RRF fusiona → reranker reordena
  8. Chat IA: Pregunta → intent router → tools internas → contexto → LLM local → respuesta grounded

6. Pipeline OCR y Preprocesado

6.1 Cascada de Motores

El sistema implementa una cascada de 4 motores OCR que selecciona automáticamente el mejor resultado usando un score de calidad:

Documento de entrada │ ▼ ┌─────────────────┐ │ Preprocesado │ Específico por motor: │ (OpenCV) │ - Tesseract: gris + denoise + deskew + binarización │ │ - Paddle: deskew + upscaling (sin binarizar) └────────┬────────┘ │ ▼ ┌─────────────────┐ ┌──────────────────┐ │ Tier 1: │────▶│ ¿Confianza > │──SÍ──▶ Resultado final │ Tesseract 5 │ │ umbral aceptable?│ └─────────────────┘ └──────────────────┘ │ NO ▼ ┌──────────────────┐ ┌──────────────────┐ │ Tier 2: │────▶│ ¿Quality > │──SÍ──▶ Resultado final │ PaddleOCR 3.5 │ │ mejor previo? │ └──────────────────┘ └──────────────────┘ │ NO ▼ ┌──────────────────┐ ┌──────────────────┐ │ Tier 3: │────▶│ ¿Quality > │──SÍ──▶ Resultado final │ PP-Structure │ │ mejor previo? │ └──────────────────┘ └──────────────────┘ │ NO ▼ ┌──────────────────┐ │ Tier 4: │ (Opcional, gated por setting) │ VLM-OCR │ └──────────────────┘

6.2 Score de Calidad

El motor "ganador" NO se decide por longitud (que favorece ruido) sino por un score compuesto:

_quality(result) = confidence × 0.5 + density × 0.3 + length_factor × 0.2

Donde:
- confidence: Confianza media del motor OCR (0-1)
- density: Proporción de caracteres alfanuméricos y espacios (penaliza basura simbólica)
- length_factor: min(len(text)/500, 1.0) — satura, no premia infinito

7.2 Búsqueda Híbrida con RRF

La fusión de resultados textuales y semánticos usa Reciprocal Rank Fusion (RRF), robusto y sin necesidad de calibrar escalas:

RRF.score(d) = Σ 1/(k + rank_i + 1) para cada lista de resultados

Donde k=60 (constante estándar). Cada fuente (texto, semántico) aporta su ranking, no su score absoluto.
Resultado: Un documento que solo aparece en semántica con alta relevancia puede superar a un match léxico débil.

8.2 Aislamiento por Presupuesto

Regla crítica: El aislamiento principal es por budget_scope_id, no por usuario o cadena. Una sesión firmada limita todas las consultas al presupuesto específico.
  • API keys: Identifican al cliente (herramienta externa)
  • Sesiones firmadas (JWT): Vinculan a un presupuesto específico con caducidad
  • Permisos por scope: can_query (consultar) y can_see_amounts (ver precios)
  • Políticas por técnico: operario_minimo (sin precios) vs precios_autorizados

8.3 Redacción de Precios

Cuando un técnico no tiene permiso para ver importes:

  • Los campos de precio se reemplazan por [IMPORTE OCULTO]
  • La redacción se aplica antes de entregar contexto a la IA externa
  • La IA no recibe precios, márgenes ni condiciones comerciales

8.4 Auditoría

  • Cada acción queda registrada en audit_logs con usuario, acción, entidad y timestamp
  • Filtros por acción, entidad y usuario en /admin/audit-logs
  • Simulador de permisos: /admin/access-explain para verificar por qué un usuario puede o no ver un documento

8.5 Webhooks Firmados

Las notificaciones a herramientas externas van firmadas con HMAC-SHA256:

  • X-DocuIntel-Signature: Firma HMAC del payload
  • Eventos: document.processed, document.failed, document.needs_review, classification.low_confidence, entity.new_pattern_detected

13. Conclusión

Docu-Intel es una plataforma completa de inteligencia documental que combina:

  • OCR industrial: 4 motores en cascada con preprocesado específico
  • IA local: Sin dependencia de servicios externos, total control de datos
  • Seguridad: Aislamiento por presupuesto, RBAC, auditoría completa
  • Escalabilidad: Workers GPU separados, procesamiento paralelo
  • Gobierno: Calidad documental, aprendizaje automático, alertas

El sistema está en producción activa, procesando documentos de presupuestos, pedidos, facturas y planos con alta precisión. La arquitectura modular permite escalar desde un servidor hasta un clúster con múltiples GPUs según la carga de trabajo.
