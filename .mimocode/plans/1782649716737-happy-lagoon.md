# Informe de prueba del Chat IA — Docu-Intel

## Resumen ejecutivo

Tras las correcciones, el chat funciona correctamente: el LLM (`qwen/qwen3-14b`) genera respuestas en lenguaje natural, los datos estructurados se renderizan como texto legible, las hojas vacías se filtran y los follow-ups son contextuales. Quedan pendientes mejoras menores.

---

## Cambios realizados

### ✅ Fase 1: LLM restaurado
- **Bug streaming:** `persist_context_after_answer()` en `ai.py:294` pasaba kwargs incorrectos (`question`, `answer_text`) en vez de los correctos (`intent`, `resolved_doc_id`). **Corregido.**
- **400 Bad Request:** Era un estado temporal de LM Studio, no un bug del código. Tras restart del backend funcionó correctamente.
- **Embeddings 400:** También transitorio, funciona correctamente.
- **Logging:** Añadido logging de response body en `local_client.py` para diagnosticar futuros 400.

### ✅ Fase 2: Calidad de respuestas
- **JSON crudo → texto legible:** `_structured_context_item()` ahora renderiza datos como texto humano en `summary` y mantiene JSON en `excerpt` para el LLM. `build_grounded_response()` usa `summary` primero.
- **Hojas vacías filtradas:** Chunks con `(Hoja sin datos)` o < 50 chars se excluyen del contexto en la rama `hybrid_search`.
- **Cache limpia:** Se eliminaron 7 entradas obsoletas que contenían respuestas en JSON crudo.

### ✅ Fase 3: Búsqueda
- **Reranker:** Ahora auto-detecta CUDA con `torch.cuda.is_available()`. Si no hay GPU, usa CPU silenciosamente sin WARNING ruidoso.

### ✅ Fase 4: UX
- **Follow-ups contextuales:** `suggest_followups()` ahora detecta entity types (factura, pedido, presupuesto) y genera sugerencias relevantes. Fallback deriva de los títulos de los documentos recuperados.
